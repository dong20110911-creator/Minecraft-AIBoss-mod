# 调用者 · 协议裂隙

## 特效、大招与战斗可行性补充 v0.4

2026-11-14 | 配套完整设计 v0.3 | 设计规格，尚未实机验证

# 01 到底要不要动作模组

**结论：内容模组不强制依赖动作模组；想让玩家也有明显的挥砍连段与翻滚表现，建议提供动作适配。** Boss 本身的独立模型、三阶段、召唤、场地招式与大招特效由本模组实现。第三方动作模组主要改善玩家这一侧，不能替我们自动完成五位 Boss。

这里的“原版向”指安装了我们的内容模组、GeckoLib 与 Curios，但没有另外安装战斗动作扩展；不是无模组客户端或纯原版服务器。

| 路线 | 玩家实际体验 | 本项目决定 |
| --- | --- | --- |
| 原版向基础 A0 | 原版攻击冷却、移动与盾；装备主动与 Boss 机制由本模组提供 | 先做可玩的基线，所有必需攻击要能靠走位 / 盾处理 |
| 动作增强 B | Better Combat 提供武器动作 / 连段；Combat Roll 提供翻滚 | 推荐作为后续展示与游玩组合；逐项测试后才标兼容 |
| 原生扩展 A1 | 自己实现持械格挡、精准奖励、短闪与相关动画 | 成本比旧稿文字暗示的高，列为实验功能，不挡首发 |
| Epic Fight C | 更完整地改动玩家战斗；自定义实体 / 武器还需专门适配 | 独立后续任务，不与 B 同时接管战斗 |

Better Combat 作者文档明确包含武器连段、挥击动作和命中计算；Combat Roll 作者列出翻滚与相关 HUD，也说明与 Better Combat 配合。[R2,R3] 因此 B 路线有现成基础，但我们的武器、主动技能与格挡逻辑仍需适配；它们不是“装上就有精准弹反”的现成承诺。

**原版式战斗能达到什么？** 可以承载有压迫感、可躲、有阶段与机制的 Boss 战；不能自动提供完整玩家动作系统。模型会动、地面有圈、伤害按时结算，也不等于已经做好了打击感。

**对之前设定的修正。** v0.3 将原版攻击与自制动作能力写在同一“基础模式”中，容易让人低估工作量。其“原版可通关”“3-5 分钟”“性能预算”都应视为验收目标，未经过模组实测。此次不承诺 AI 一次生成就能达到这些效果。

**文件定位。** 本补充 v0.4 与完整设计 v0.3 配套；只覆盖动作路线、特效、大招及相关可实现性描述，世界观、成长、遗迹、掉落仍沿用主稿。当前仍为设计阶段，没有可安装 Jar 或游戏实录。

# 02 哪些地方此前说得太满

技术可实现、做起来省事、已经验证，是三种不同结论。五位 Boss 的有限状态与机制具备实现路径，但完整动作、手感、联机同步和美术资产需要逐项制作；上一版对这部分工作量交代不够充分。

| v0.3 的表述 / 容易形成的印象 | 本补充的正式修正 |
| --- | --- |
| 基础模式含 4 tick 精准格挡 | 原版盾已有举起后生效的延迟；不能把“按键后四 tick”直接当现成弹反窗口。精准奖励列实验项，先验证实际格挡事件与时钟 |
| 原生普通武器有二段 / 三段连招 | 不装动作扩展时，先只做连续合法命中的段序 / 效果；完整玩家身体连段另需动画与控制，不是改一个数字 |
| 0.25 秒受击硬直 | 不视作原版玩家自带能力；首发不强制冻结玩家输入。Boss 倒地与中断由自己的状态机实现 |
| 无无敌帧短闪即可完整通关 | 短闪不证明可通关。A0 完全不用它，先按步行、盾与攻击冷却验证；翻滚只能增加容错 |
| 装动作模组即可拥有原设全部机制 | 动作模组各自只解决部分内容；Boss、场地、武器主动、姿态、奖励与同步仍由本项目承担 |
| 每秒 120 粒子足以界定特效强弱 | 粒子数不是画面质量 / 性能定律；改用网格轮廓、透明覆盖、贴图、批次和实测共同控制 |

原版盾存在非即时生效的行为，Mojang 问题记录 MC-100949 可查。[R5] 本补充不把最新 Minecraft 的盾组件配置倒套到 1.20.1；若保留精准奖励，需要在锁定版本用实际代码 / 运行行为验证。首发 Grok 只抽躲避挑战，不生成必须精准格挡的条件。

**A0 保留的能力。** 玩家装备主动可使用专注；普通盾按原逻辑；本模组在实际成功承击后给予允许的机制反馈。持械格挡减伤 60%、按承击扣专注、精准奖励和短闪归 A1。A0 不偷偷复制它们，再把这套工作称为“只用原版”。

**武器表现的边界。** 原版不会因为物品叫“双刃”就让双手自动舞起来；A0 使用清楚的持械造型与主动技效果。B 路线再做对应武器属性与动画，并核查双持、双手武器与副手盾的实际规则，不照搬默认增益导致额外攻速失衡。[R2]

**可以保留期待。** 三阶段、有限后手、双向条款、可改造构件、公开挑战、大招轨迹都是明确的程序与资源任务。它们不是无法落地的空想，但“把规格写得完整”不能替代做完模型、动画、命中和试玩。

# 03 强特效：轮廓、蓄势、兑现与余波

**视觉目标：远处认得出是谁，起手看得出要出事，命中知道为什么，结束抓得到反击。** 每位首发只做一个标志大招，把普通技、阶段变化和这个大招做成同一种角色语言；不额外堆五套脱离人设的元素法术。

| 层次 | 画面职责 | 制作方式 |
| --- | --- | --- |
| 主体轮廓 | 形成“大事要发生”的第一印象 | 受控的鲸形任务影、双重门环、展开巨书、构件蓝图、巨大斧痕；简单自定义网格 / 平面 |
| 蓄势 | 引导视线、建立时间感 | 手势、武器停顿、符号收拢、边缘节点变亮与递进声音 |
| 真实危险 | 明确攻击区域与锁定时刻 | 地面边线、箭头、序号；与服务端判定共用几何参数 |
| 兑现 | 让攻击有重量 | 1-2 个清晰的冲击面、短刀光、少量碎屑、低频重音；不靠持续白屏 |
| 余波 | 解释空窗与能力耗尽 | 门环熄灭、任务退回、封条断落、半成品解体、斧回手后的停顿 |

**角色符号的用法。** DeepSeek 的鲸影承载“任务汇集”，实际攻击是任务落点；GPT 的门环是可数后手；Claude 的书页 / 封条显示限制与解除；Gemini 的蓝图表明未完 / 补完；Grok 的斧线对应去程、落斧与回收。外观符号做识别，性格决定行动逻辑。

**大招规模分两层。** 主轮廓可高约 8-12 格，放在 Boss 后上方或场地外沿；实际伤害维持可躲的局部区域。装饰性巨大轮廓采用虚线 / 低密度，真实危险采用实线与倒计时，图鉴先说明。不能画出“整片地面都被打中”却只在中心扣血。

**阶段抬升。** P1 显示角色的基本手势与符号；P2 在既有机制动作里露出大招的一拍或局部轮廓；P3 完整兑现。前奏只强化原有招式的表现，不暗中追加一段伤害。这样让高潮提前埋下印象，也控制新资产数量。

**演出约束。** 不锁玩家镜头，不强制第三人称，不暂停服务器时间；默认不做全屏闪白。可关闭震屏与暗角；关闭装饰粒子仍有攻击边线、方向与音效。发光贴图不等于照亮周围世界，更不等于自动拥有光影包里的 Bloom。

**统一大招流程。** 准备 → 锁定 → 兑现 → 收招。准备中可转向，锁定后不追踪脚下；攻击部分按服务端 tick 结算，客户端可用更平滑插值。画面强度不改变一次命中的计数，也不让一片装饰碎屑变成一次伤害。

后面五页给出可交给开发者的具体时间轴。所有伤害为护甲前设计初值，位置与时间仍需 A0 试玩校准；20 tick = 1 秒。

# 04 DeepSeek 大招：万事转包 · 集中清账

**战斗含义。** 她把所有积压委托一并派出，任务在玩家周围依次兑现；最后因为清算完毕暴露本体。大场面来自“任务洪流”，鲸形只作为社区形象的远景识别。沿用 v0.3 的 P3 一次集中清账，不增加第二套终局机制。

| 时间 / tick | 动作、画面与实际判定 |
| --- | --- |
| 0-30 / 0-1.5 秒 | 清掉旧小工与旧任务；三枚任务章升起，场外蓝色鲸形轮廓被纸带填满。只有蓄势，不扣血 |
| 30、48、66 | 依次记录目标当前位置并锁住三个圆，标明 1 / 2 / 3；每圆半径 2.2 格，各有 30 tick 预警 |
| 60、78、96 | 对应任务章拍落：每个圆一次 10 原始伤害。圈外纸带只在上方通过，不造成线形伤害 |
| 96-146 / 后 2.5 秒 | 任务流全部倒回，鲸影裂散；本体停手，不召新小工、不架碗，提供明确输出窗 |

**高潮画面。** 从侧后方看，是一条约 10 格长的任务鲸影随三次章落逐段散开；从第一人称看，注意力仍能落在脚下下一枚编号与她的手势。三次低音按相同间隔推进，最后一次用清脆“退回”声提示空窗。

**原版解法。** 位置锁定后步行离开圆，顺势向侧面绕；不需要无敌翻滚。攻击按可见位置依次兑现，不能刚躲开 1 号又在同一 tick 生成一个无前兆 2 号。多名玩家只锁最多两名轮换目标，场上仍只有三枚任务，不按人数增殖。

**地形与交互。** 圆只落在主场可见且有合法支撑的区域；不能在屋顶播放而在屋内扣血。玩家暂时用水 / 掩体脱险有价值，位置生成与可达性仍按主稿处理。每次选择都要确认有步行安全区域，不能让三圈封满唯一通道。

**资源与实现。** 一个鲸影薄网格、一个任务章网格、一套纸带、三个地面圆，复用小工离场效果。鲸影无 AI、无碰撞、不改海水，不生成上百实体；实际伤害就是三次圆形时间线事件。

**触发与清理。** P3 入场一次；若玩家合法高伤直接击败，允许中断，不锁血强演。结束 / 死亡 / 会话中止关闭剩余圆与任务效果；不得因客户端鲸影还在就继续扣血。降装饰质量时仍保留鲸影外轮廓、三次任务落点与收招提示。

# 05 GPT 大招：最终答复 · 双重闭环

**战斗含义。** 她把最后两份准备明确摆出，连续接住玩家的两种选择；用尽后不再补库。一次完整演出约 7.5 秒，危险来自可看懂的连续响应，而不是满屏激光或无穷护盾。

**对 v0.3 的局部覆盖。** P1 / P2 继续使用条件触发后手。P3 的最后两枚储备改为一次公开顺序的终局行动，取代“等条件触发或 20 秒到期”的分散兑现；不会另外再发两份大招弹药。进入 P3 后先清旧后手，建立同一份最终库存。

| 时间 / tick | 动作、画面与实际判定 |
| --- | --- |
| 0-30 | 三层门环收拢，其中一层保持熄灭；两枚储备亮起，显示接下来“直线答复 → 延时标记” |
| 30-60 | 消耗第一枚；一条长 12 格、全宽 3 格的答复线锁向，30 tick 后兑现一次 8 伤害 |
| 70-100 | 消耗第二枚；记录目标当前站位，半径 2.2 格圆标记预警 30 tick，再兑现一次 8 伤害 |
| 100-150 | 两枚图标熄灭，门环由外向内散开，2.5 秒整理；此后仅保留常态招式与既定进攻空隙 |

**高潮画面。** 第一轮是一扇竖门展开为薄的答复光面，第二轮是小幽灵把未闭合的环压向落点；两道半透明“备选姿势”只在她身后短现。每一层都能被数出来，终局后看见的是资源耗尽，不是切入无敌形态。

**原版解法。** 先横移出线，再在第二个圆锁定后移动；两个命中时点相隔 2 秒。盾对可挡直线的处理依具体伤害源验证，地面延迟标记通过移动解决。绝不要求穿过光面翻滚，也不在玩家已经躲开后把圆重新拉回脚下。

**统一账本。** 两次终局响应各占用一枚最终后手，顺序调度与普通后手共用库存服务。不能一边播大招一边被靠近再触发第三次护波。旧储备到期计时、旧标记与普通防御不得抢掉整理窗；P3 不再补库存。

**资源与实现。** 门环与光面使用少量可缩放网格，幽灵沿用原模型；只有两次真实伤害。发光感靠贴图与明暗层次，默认不依赖外部光影。死亡 / 越阶段直接关闭未执行项；已经发出的普通弹按主稿规则独立处理。

# 06 Claude 大招：限制解除 · 完整回答

**战斗含义。** 原先被条款按住的最后一段终于打完，同时她也失去封约保护。大招沿用 P3 的 8 秒解封与已预告过的完整连段；三击有递进动作，不加一套与人格无关的天罚。

| 时间 / tick | 动作、画面与实际判定 |
| --- | --- |
| 0-30 | 暂停并清空旧规则累计；封条从手腕断开，巨书在背后展开约 8 格高。可移动、可受伤，不扣血 |
| 30-50 | 书脊前推，窄扇形准备；50 tick 时一次 6 伤害，可普通格挡 / 绕侧 |
| 50-66 | 转身合书第二击，独立起手；66 tick 时一次 7 伤害，可格挡，不瞬间转身追背 |
| 66-96 | 被压住的第三击充分蓄势；脚下出现长 10 格、全宽 3 格的展开线，96 tick 兑现一次 10 伤害 |
| 96-132 | 书页回卷，固定 1.8 秒收招；整段解封期间禁止合书架势，直到 160 tick 才结束 8 秒撤约 |

**高潮画面。** 巨书不是实体墙；书页展开成短促的“回答段落”，每击只亮起当前段。第三击沿公开地面线铺开一道厚重橙白纸面，碎封条从上方向两侧飞开，脚下边线仍可见。没有全屏密集文字墙。

**原版解法。** 走位避开全部三段，或盾处理前两段，再侧移第三段。第三段定义为地面危险，不能靠举盾原地吃完，但也不需要弹反。前两击的普通受击不冻结玩家输入，避免被动锁进第三击。

**条款恢复。** 8 秒解封的最后 3 秒只预告下一条，不统计；160 tick 恢复规则时重新累计。过场停留、旧三连射计数不带入。首次 P3 的解封必有演出；之后按主稿至少 24 秒间隔，重新解封时可复用该连段，不每次重播大型展开书景。

**资源与实现。** 一套巨书平面骨架、两种封条、三段动作、一个展开面。书页不生成几十个真实方块，不删除地形。Boss 动画与规则计时由服务端发事件驱动，动画失败不能使规则永远暂停。[R4]

**边界。** 维持“解封更危险，也更暴露”的交换。不得同时给她全向无敌或隐藏护盾；姿态破坏、合法击败与会话结束均可终止剩余攻击。第三击是大招主重音，粒子不能盖住它的线形范围。

# 07 Gemini 大招：这次一定 · 最终定稿

**战斗含义。** 她强行把已经摆出的两个点子做成成品，再试一次变奏。玩家之前改过的方向、拆过的拉索仍然生效。震撼来自“半个场景正在被拼好”，危险仍来自可识别的两个真实构件。

| 时间 / tick | 动作、画面与实际判定 |
| --- | --- |
| 0-30 | 公开当前构件 A / B 的顺序。缺件可在安全边缘补足，但不足观察时间时将首拍顺延，至少给新件 2 秒辨认 |
| 30-54；56-80 | A / B 各有 24 tick 补完预警，54 与 80 依序兑现；两者有效时点至少间隔 16 tick |
| 100-124；126-150 | 同一顺序再演一轮；先公开变奏位置，不新增第三种构件，不偷偷纠正玩家转向 |
| 150-210 | 构思终于停住，3 秒反击窗；构件无伤解体，场景蓝图回到不完整的外框 |

**高潮画面。** 约 10 格高的半透明蓝图框从远处逐块闭合，外侧可见半桥、立柱和几何星饰的错位剪影；只在当前 A 或 B 周围变成实线。场外虚线构件不碰撞、不落下。两个真实机关足以支撑一幕大场面，不需要实时生成整座城。

**伤害与交互不变。** 箱体一次 9；烟花每枚 3、同轮同目标最多两枚；弹板本身无伤且有落地保护。烟花、箱体和弹板都按原有实体状态兑现，玩家转向 / 提前拆除成功后，这一拍可以落空，仍按时给出终局收招。

**寿命与数量。** 仍最多两件，最长保留 25 秒；P3 不借演出复活已到期构件。自然到期或被拆掉的后续拍只剩无伤轮廓，演出可以被玩家实际拆解。若新补构件，需要记录新实例，不继承旧实例的姿态奖励次数。

**原版解法。** 顺序明确后逐个绕开；可以先改方向、提前放下箱体，或用弹板离开危险区。没有要求玩家跳上高速移动平台，也不把它做成第一版就要处理的立体跑酷战。构件反用收益每件只结算一次，重复两轮不重复刷姿态。

**资源与实现。** 原有三类构件配一套可拼接蓝图网格、补完描边与解体效果。构件烟花场上最多三枚，上一拍仍有弹体时延后下一次同类发射；不无限叠加。死去 / 中止立即清理蓝图；降级仍保留蓝图主轮廓、A/B 序号与两件机关。

# 08 Grok 大招：全网见证 · 全押终局

**战斗含义。** 她把终局三击当众说清，给玩家一次自愿接下挑战的机会，随后押上自己的大收招。拒绝挑战不影响正常战斗和掉落；终局高潮不能藏在一个新玩家不敢按的按钮后面。

**对主稿的细化。** 原“横斩 → 重劈 → 回收”需要斧先离手。因此第二段明确为“掷斧重劈”：同一把斧沿已锁定轨迹砸落，然后回收，避免手里一把、场上一把的状态错误。

| 时间 / tick | 动作、画面与实际判定 |
| --- | --- |
| 0-30 | 挑战圈显示“避开终局三击”，站入 16 tick 即接受；不接受也播放同一套攻击预告 |
| 30-54 | 巨斧横斩起手，扇形外边线清晰；54 时近距一次 8 伤害 |
| 54-84 | 同一把斧掷出重劈，锁定长 12 格、全宽 3 格地面线；84 时一次 12 伤害，身体不能再播持斧攻击 |
| 90-110 | 折返线至少预告 20 tick；110 时回收一次 8 伤害，同目标每段只命中一次 |
| 110-160 / 170 | 无条件至少 2.5 秒收招；赴约成功延至 3 秒，并给主稿中的姿态与专注奖励 |

**高潮画面。** 斧实际模型保持合理大小，拖出的黑红斧痕在上方扩大；主场边缘投影同时倾向中央，低音在重劈时落下。地面的真实切线独立高亮，回收用反向箭头与更尖的提示音，第一人称也能辨认。

**原版解法。** 退开横斩扇形，侧移离开重劈线，再避开已公开回收路径。直击 / 重压与地面线分别定义伤害类别；不把重斧造型当作原版必然破盾的证据。该终局不依赖精准格挡、无敌帧或高跳。

**挑战结算。** 同时一位赴约者；完整合法在场、成功处理三击才记成功。离开有效挑战区不算完成，队友代挡也不替他完成；失败不补一发额外处决。挑战分支只增加反制收益，不决定大招是否能躲开。

**资源与实现。** 一个独立飞斧对象，持有 / 掷出 / 回收三态，三次时间线判定，复用普通斧痕与场边投影。终局每场只一次；之后回到 P2 攻防。回收失败 / 玩家死亡 / 会话结束必须关闭对象与残留伤害，不能刷出可拾取复制品。

# 09 普攻、格挡与反击也要有分量

大招之外的多数时间仍在普通攻防。每位先把 3-4 组常态招打磨好，再做终局；否则只有几秒特效，剩下时间仍像高血量普通怪。

| 环节 | 必做表现 | 实际规则 |
| --- | --- | --- |
| 普攻起手 | 肩、腰、手臂与武器先蓄势，角色视线 / 身体转向可读 | 前摇后段锁向；挥空不能瞬间回头追人 |
| 连段接续 | 每一段独立动作、短停顿与不同重音 | 只按真实合法攻击推进；不能每帧 / 每粒子都算一击 |
| 普通命中 | 接触点短闪、薄刀光与材质音；躯干轻反馈 | Boss 能按状态受击，不能每次轻击都被无限打断 |
| 盾挡成功 | 盾缘火花、弹开轨迹与短促承击声 | 有实际成功承击才播放，不重复减伤、不伪报精准格挡 |
| Boss 架势 | 正面清楚摆出防御，侧后保持可读 | 沿用有限减伤与冷却；不因特效像屏障就额外无敌 |
| 姿态崩解 | 支撑点失稳、武器下垂、机制符号短暂熄灭 | 倒地与保护计时是服务端状态，客户端不能多延长 |
| 大收招 | 胸肩 / 武器明显回落，音色结束 | 玩家看见才敢反打；不能动画像疲惫却继续藏一刀 |

**角色区别。** DeepSeek 用“交出去 / 退回来”的手势接小工；GPT 的双重确认有清楚对称与整理；Claude 第三击在被束缚 / 解封时形成对比；Gemini 在两个动作间改主意但危险不突然跳位；Grok 的重斧借腰胯发力，有完整回正过程。

**玩家表现的分工。** A0 保留原版挥手，主动技可有独立武器特效；B 使用已适配的连段动作，不能同时再用本模组覆写一套玩家骨架。GeckoLib 能驱动我们的实体 / 物品动画，不自动给原版玩家身体安装完整格斗动作。[R4] 第一人称、第三人称必须分别验收。

**打击停顿。** 允许给本地武器特效或动画极短的视觉强调，但不暂停服务器 tick，不冻结其他玩家，也不让镜头停顿扩大实际格挡窗口。首发可完全不用停帧，靠声画同步、接触反馈与收招先做好重量。

**盾与连段不能一招鲜。** 普通招允许盾解；地面招要求移动；有限后手、条款、构件和挑战提供不同决策。不能所有大招都标“不可挡”来掩盖格挡系统没接好，也不能一面盾原地不动挡完所有机制。

# 10 特效怎么实装，以及哪些最费工

**核心做法。** Boss 动画、短促自定义网格、透明贴图、轨迹带、地面预告与声音组合。Forge 的粒子系统支持自定义显示与服务器通知，GeckoLib 4 支持服务端触发动画；这些提供实现接口，并不自动生成美术资源或同步伤害。[R1,R4]

| 资产 / 服务 | 首发范围 | 难点与控制 |
| --- | --- | --- |
| 共用特效库 | 圆、线、扇形、轨迹带、冲击面、碎屑、符号环 | 一套参数驱动外观与判定，贴图打图集；实际实现后再优化批次 |
| 五个大招主轮廓 | 每人一件轻量网格，主要是鲸影、门、书、蓝图和斧痕 | 不是五只新大生物；需要美术资源、动画与渲染代码 |
| 角色机制显示 | 库存、条款、构件状态、赴约者与倒计时 | 与服务端快照一致；多人不能各自看不同安全区 |
| 发光感 | 自发光 / 全亮显示与亮暗贴图对比 | 不保证真实照明或 Bloom；外部光影作为额外测试环境 |
| 全屏后处理 | 首发不依赖 | 屏幕扭曲、景深、时间停滞、复杂体积雾均不进必需范围 |

**网络契约。** 服务端发送 encounter_id、action_id、start_tick、sequence、seed、锁定几何与剩余状态。客户端渲染本地插值；重连补快照，中途进入不重播从头爆发。迟到包不得让已过去的视觉与伤害重复执行，正式伤害从不由动画关键帧回调直接判定。

**预算替代旧粒子硬数。** 初版每场同时最多一个主大招轮廓、两个主要透明冲击层、三处待命危险预告；装饰粒子设本地存活上限与降级开关。先用普通档约 200、低档约 60 个存活装饰粒子做测量起点，不作为性能保证。关键边线独立渲染，不因“最少粒子”设置而消失。

**时间 / 形状归属。** 伤害形状与锁定点由服务端产生；客户端可以把一条线绘得细腻，不能自己随机偏移线的位置。骨骼 / 武器轨迹用于表现，攻击判定按已定义几何，不依赖显卡端骨骼计算。

**资源可行性。** 平面与程序生成网格能降低绘图门槛，精细角色动作与特效纹理仍要制作和修改。AI 可以帮助写渲染代码、生成初始图案或资源脚本，不能承诺一次输出就能得到视频里成熟模组的质感；需要游戏内多视角调节与素材来源记录。

**实现顺序。** 地面圆 / 线与一个冲击面 → 一套普通攻击 → 一个完整大招 → 多人同步 → 五位复用。先跑没有光影包的画面，再测可能的渲染优化 / 光影组合；透明排序、深度、穿墙可见与 Z 闪烁单独检查。

# 11 大招更强，通关要求仍需算清

**A0 的承诺改为发布门槛。** 不装动作扩展，穿铁甲、持远征武器与盾，用原版走位实际通过五战；未完成试玩前，不写“已经可以完整通关”。B 的翻滚应提升容错和表现，不能成为躲开一个基础招的唯一办法。

| 必测问题 | 可执行检查 |
| --- | --- |
| 有时间离开预告吗 | 用锁定后预警时长，扣除可接受反应 / 延迟余量，再乘实际移动速度；检查是否超过最近安全边界距离与碰撞余量 |
| 同时危险是否无解 | 逐阶段检查所有攻击交叠；保持至少一条连续可步行路径，不能上一击击退后必吃下一击 |
| 水、减速与障碍怎么办 | 分别测试流体 / 负面状态 / 临时方块；自选风险可增加难度，不能修成隔墙必中或瞬时改落点 |
| 预告和命中吻合吗 | 调试叠加判定体，四方向观察；刀光外围可装饰，危险实线必须准确 |
| 多人是否惩罚翻倍 | 不随人数倍增圈与实体；锁定对象、序号与库存共享，未入场者不偷触发后手 |
| 网络不佳能读懂吗 | 本地与约 100 / 200ms 往返延迟各测；记录实际预警与丢包恢复，不假定设计时长就是到屏时长 |

**计算示例，只是验算。** 以锁定后 1.5 秒、反应 / 网络保守余量 0.4 秒、实际移动速度 3 格/秒作测试输入，可移动 3.3 格。若圆半径 2.2 格、身体与边界余量 0.4 格，中心出发所需约 2.6 格，几何上有余量；水推、墙角与被击退后的实际速度必须另测。这里的 3 格/秒是测试假设，不冒充原版固定速度。

**大伤害的边界。** 延续主稿普通 5-9、重招约 9-13 的原始伤害起点。特效升级不把每枚碎屑变成额外伤害，也不把三次脉冲在同一帧结算；原版受伤保护与多段命中间隔要检查，不为“看起来连上”全局关闭受伤保护。

**屏幕可读性。** 最多突出一个当前主危险与下一个预告；装饰轮廓放侧后方；低特效仍留关键形状与声音；镜头震动可关。主大招时暂停会压住同一目标逃生路径的普通重招 / 召唤物协同，不能把清晰机制叠成随机死局。

**性能结果怎么报告。** 固定硬件、场地、视距与依赖，对比无战斗、普通战斗、大招峰值；分别记录帧时间、服务器 tick、透明覆盖与实体数量。前版 20 TPS / 增量耗时数字保留为测试目标，不能提前宣称达到。低档必须保留大招主轮廓，优化优先减碎屑、后处理与叠层。

# 12 开工顺序与覆盖主稿的清单

**先做有说服力的一战。** 完成主稿 M0 / M1 后，用 DeepSeek 制作普通攻击、委托退回、P3 清账与一次胜利结算；做到第一人称和第三人称都能看懂、能躲、能反击，再复用共通特效库给另外四位。一个小而完整的原型比五段纯演示动画更能证明可实现性。

| 检查关口 | 交付证据 |
| --- | --- |
| 灰盒机制 | 无特效或极简预告也能看懂；伤害、库存、阶段和清理正确 |
| 动作重量 | 普通攻击前摇 / 命中 / 收招；盾挡、姿态与反击窗真实有效 |
| 第一版大招 | 一份主轮廓、完整时间轴、对应音效；不锁镜头，也不只剩几圈原版粒子 |
| A0 通关 | 普通装备、无动作扩展、无精准格挡与短闪，录下完整战斗 |
| B 适配 | 同一 Boss 加 Better Combat + Combat Roll；武器动画、命中、盾 / 翻滚互斥与掉落验证 |
| 双人 / 性能 | 延迟、阶段跨越、死亡中止、重复事件、最低特效与大招峰值记录 |

**将本页交给 Claude / GPT 时的执行要求。** 读取 v0.3 主稿与本 v0.4 补充；保留原有架构与任务边界。先确认真正工程状态，再做当前一个可验收目标。大招时间表是待实现规格，不要交付只有粒子调用而没有锁定、判定与收招的空壳。

**覆盖关系。** ① 原“基础模式”拆为 A0 与实验 A1；② 完整玩家连段不视作原版已有；③ 精准格挡、输入硬直与短闪不阻塞首发；④ GPT P3 两枚后手用于一次公开终局顺序，不重复发库存；⑤ Grok 终局第二段明确为掷斧重劈；⑥ 粒子预算改为主轮廓 / 覆盖 / 存活数量与性能实测；⑦ 五位大招使用本补充时间表。其余主稿仍有效。

**哪些内容不降。** 独立实体、角色辨识度、三阶段、真实危险轮廓、可反制机制、明显大招高潮与反击窗。原型允许纹理粗一些、场外背景简单些，但不能通过删光轮廓只留几颗粒子来声称“优化完成”。

**哪些不进首轮。** Epic Fight 全适配、玩家原创全套动作、复杂布料、电影级后处理、真正改变海水 / 地形的大招、任意生成建筑和实时 AI 对话。它们的缺席不阻止五位按既定机制战斗。

**交付状态。** 本次完成的是补充设计与可行性校正。没有新增游戏模型、贴图、动画、渲染代码或试玩录像；也没有实测任何动作模组组合。需先做原型，才能判断实际质量、工时与机器性能是否满足预期。
